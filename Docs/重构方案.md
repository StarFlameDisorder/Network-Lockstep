# Factory 重构方案

## 一、当前架构问题

### 1.1 层间耦合混乱

当前依赖关系呈平铺耦合，各层互相直接调用：

```
PlayerController ──→ GameSync ──→ NetworkManager
     │                   │              │
     │                   ↓              ↓
     │              StatusPanel    TcpSocket/UdpSocket
     │                   │         MessageDispatcher
     └───────────────────┘
```

**核心问题：**
- **三层未分离** — GamePlay / Network / UI 之间无接口隔离，互相直接调用
- **跨层调用无事件机制** — 网络数据到达 → 触发游戏逻辑 → 更新 UI，全部是直接方法调用 + 单例访问

### 1.2 单例模式滥用

- `GameSync.Instance` — 帧同步控制器全局单例
- `NetworkManager.Instance` — 网络管理器全局单例
- `StatusPanel.Instance` — UI 面板全局单例

多个全局单例散落各处，导致：
- 模块间紧耦合，无法单元测试
- 依赖关系不透明，谁依赖谁都看不出来
- 生命周期无法集中管理

### 1.3 GameSync 上帝类

`GameSync` 同时承担以下 6+ 项职责，远超一个类的合理范围：

| 职责 | 说明 |
|---|---|
| 网络消息注册与接收 | `RegisterHandler`、`ReceiveMessage`、`ReceiveSnapshotMessage` |
| 房间管理 | `JoinRoom`、`LeaveRoom`、`StartRoom`、`AddPlayer` |
| 帧同步主控 | `SyncPlayerAction`、`PlayerAction`、`UpdateGame` |
| 快照生成与发送 | `SyncSnapshot`、`GetSnapshotSync`、`SetSnapshotSync` |
| 心跳发送 | `HeartBeat` |
| 游戏状态生命周期 | `StartGame`、`PauseGame`、`ContinueGame`、`EndGame` |
| UI 状态更新 | 直接调用 `StatusPanel.Instance` |

### 1.4 Player 实体与表现耦合

`Player` 类同时包含：
- 逻辑数据（位置、速度、帧缓存）
- 表现层操作（直接修改 `GameObject.transform`）

导致逻辑不可独立测试，且帧同步确定性计算与渲染帧耦合。

### 1.5 网络层线程安全缺失

- `MessageDispatcher` — 多线程读写 `_handlers` 字典无锁
- `UdpSocket` — `_pendingPackets`、`_receiveBuf` 在多线程环境下无同步
- `TcpSocket` — 使用 `async void`，未捕获异常直接崩溃

### 1.6 配置硬编码

幻数散落在代码中：

| 参数 | 值 | 位置 |
|---|---|---|
| `BufferSize` | 3 | GameSync.cs / Player.cs |
| `MaxCatchupTime` | 5 | GameSync.cs / Player.cs |
| `_gameFrameRate` | 30 | GameSync.cs |
| `_snapshotSpacing` | 10 | GameSync.cs |
| UDP 缓冲区大小 | 600 字节 | UdpSocket.cs |
| TCP 缓冲区大小 | 2048 字节 | TcpSocket.cs |

### 1.7 其他代码质量问题

| 问题 | 严重程度 | 位置 |
|---|---|---|
| `async void` 模式，异常无保护 | 必须改 | TcpSocket.cs, UdpSocket.cs |
| 字典重复 Key 无保护 | 推荐改 | Player.cs `AddSyncMessage` |
| Socket 操作无 try-catch | 推荐改 | TcpSocket.cs, UdpSocket.cs |
| `IDisposable` 模式缺失 | 推荐改 | TcpSocket.cs, UdpSocket.cs |
| 重连状态重置不完整 | 推荐改 | UdpSocket.cs `CloseLink` |
| 死代码（空方法、注释日志、未用字段） | 推荐改 | 多个文件 |
| 拼写错误 `_playerSyncMessgae` | 可选改 | Player.cs |
| 枚举命名不一致 `Notstarted` / `Pause` | 可选改 | GameSync.cs |
| 字段命名风格不统一 | 可选改 | NetworkManager.cs |

## 二、目标架构

### 2.1 分层设计

```
┌─────────────────────────────────────────────┐
│                  UI Layer                    │
│   LobbyPanel  StatusPanel  MessagePanel     │
│         ↑ (监听事件)        ↑ (监听事件)       │
├─────────────────────────────────────────────┤
│              GamePlay Layer                  │
│   FrameSyncController  GameStateMachine     │
│   PlayerEntity(纯逻辑)  RoomSession          │
│   HeartBeatService     SnapshotService       │
│         ↑ (通过接口)     ↑ (通过接口)          │
├─────────────────────────────────────────────┤
│              Network Layer                   │
│   INetworkClient (TCP/UDP)  MessageBus       │
│   NetworkConfig                              │
└─────────────────────────────────────────────┘
         ↑ (配置注入)
┌─────────────────┐
│  GameConfigSO    │
│  ScriptableObject│
└─────────────────┘
```

### 2.2 核心设计决策：Global + GameCore

采用 **Global 静态门面 + GameCore MonoBehaviour 运行时容器** 的组合方案：

```csharp
// 纯静态门面，基础设施入口
public static class Global
{
    public static GameCore Core { get; internal set; }
}

// MonoBehaviour 运行时容器，持有所有子系统
public class GameCore : MonoBehaviour
{
    void Awake()
    {
        Global.Core = this;
        DontDestroyOnLoad(gameObject);
        // 初始化所有子系统
    }

    void OnDestroy()
    {
        // 有序关停所有子系统
        Global.Core = null;
    }

    public INetworkService Network { get; private set; }
    public IEventBus EventBus { get; private set; }
    public IUIService UI { get; private set; }
    public IGameService Game { get; private set; }
    // ...
}
```

**使用约束：**
1. `Global.Core` 中只放接口，不放具体实现类
2. 业务代码优先通过构造函数注入获取依赖，MonoBehaviour 可兜底走 `Global.Core`
3. `Global` 和 `GameCore` 不包含业务逻辑，只做注册、获取、生命周期管理

### 2.3 具体拆分方案

#### GameSync 拆分

```
GameSync (当前) → 拆分为 6 个独立类:
├── RoomSession          — 房间生命周期（加入/离开/开始/结束）
├── FrameSyncController  — 帧同步主控（收集输入、广播、推进帧）
├── SnapshotService      — 快照生成与恢复（断线重连）
├── HeartBeatService     — 心跳发送与超时检测
├── GameStateMachine     — 游戏状态机（未开始/进行中/暂停/结束）
└── TickTimer            — 计时器管理（FixedRate 触发）
```

#### Player 拆分

```
Player (当前) → 拆分为:
├── PlayerEntity         — 纯逻辑数据类（位置、速度、帧缓存、快照状态）
└── PlayerView           — MonoBehaviour，从 PlayerEntity 读取数据更新 Transform
```

#### 网络层重构

```
NetworkManager (当前) → 拆分为:
├── INetworkService      — 网络服务接口
├── NetworkClient        — 实现类，组合 TcpChannel + UdpChannel
├── TcpChannel           — TCP 通道（重构 TcpSocket）
├── UdpChannel           — UDP 通道（重构 UdpSocket，修复线程安全）
├── MessageBus           — 消息总线（替代 MessageDispatcher，线程安全）
└── NetworkConfig        — 网络配置（IP、端口等）
```

### 2.4 关键变更一览

| 当前 | 重构后 |
|---|---|
| 多个 `Instance` 单例散落 | `Global.Core` 统一入口 |
| `GameSync` 上帝类 | 6 个独立类，各司其职 |
| 各层直接调 `StatusPanel.Instance.xxx` | 事件驱动，UI 层订阅 |
| `Player` 操作 Transform | `PlayerEntity`（纯逻辑）+ `PlayerView`（表现层） |
| 硬编码参数 | `GameConfigSO` ScriptableObject 统一管理 |
| `NetworkManager.Instance` 全局调用 | `INetworkService` 接口注入 |
| 无线程安全的网络层 | MessageBus + 通道加锁 |
| `async void` | `async Task` + 异常保护 |

## 三、重构执行计划

### 第一步：基础骨架建立
- 创建 `Global` 静态类
- 创建 `GameCore` MonoBehaviour
- 定义核心接口：`INetworkService`、`IEventBus`、`IUIService`、`IGameService`
- 创建 `IEventBus` 实现（事件总线，线程安全）
- 创建 `GameConfigSO` ScriptableObject 配置资产

### 第二步：网络层重构
- 创建 `MessageBus`（替代 `MessageDispatcher`，线程安全）
- 重构 `TcpSocket` → `TcpChannel`（修复线程安全、async/await、IDisposable）
- 重构 `UdpSocket` → `UdpChannel`（修复线程安全、缓冲区、重连状态）
- 创建 `NetworkClient` 统一入口（实现 `INetworkService`）
- 将其挂载到 `GameCore`

### 第三步：GameSync 拆分
- 创建 `RoomSession`、`FrameSyncController`、`SnapshotService`、`HeartBeatService`、`GameStateMachine`、`TickTimer`
- 逐步将 `GameSync` 中的逻辑迁移到各独立类
- 确认帧同步正常后删除 `GameSync`

### 第四步：Player 数据表现分离
- 提取 `PlayerEntity` 纯逻辑数据类
- 创建 `PlayerView` 负责渲染同步
- 接入事件总线通知位置变化

### 第五步：UI 层解耦
- 将 UI 面板改为事件订阅模式
- 消除所有 `StatusPanel.Instance.xxx` 的直接调用
- UI 层通过 `IUIService` 接口暴露给外部

### 第六步：配置外置收尾
- 将所有幻数迁移到 `GameConfigSO`
- 清理死代码（空方法、注释日志、未用字段）
- 统一命名规范

### 第七步：服务端同步清理
- 修复 UdpServer 头文件引用
- GameServer 析构函数停止网络线程
- 统一命名风格

## 四、补充说明

### 判断标准：MonoBehaviour vs 普通 C# 类

| 需要 Unity 生命周期/协程/编辑器反射的 | 纯逻辑可独立测试的 |
|---|---|
| GameCore（组合根） | EventBus |
| PlayerView（渲染表现） | PlayerEntity |
| UI 面板 | FrameSyncController |
| TcpChannel / UdpChannel | RoomSession |
| HeartBeatService | GameStateMachine |
| SnapshotService | NetworkConfig |

### 优化建议分级标准

- **[必须改]**：逻辑错误、安全漏洞、资源泄漏
- **[推荐改]**：低成本、可感知收益的改进
- **[可选改]**：锦上添花，不改无影响
