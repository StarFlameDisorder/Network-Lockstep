# 帧同步框架架构设计（指南）

> 创建于 2026-08-03 | 给 Agent 和开发者看的设计思路 + 类联系速查
> 核心原则：**网络同步是唯一目标**；框架/游戏逻辑分离（Quantum 风格）；保持简单，不为假设需求过度设计

---

## 一、分层模型（帧从哪来、到哪去、谁执行）

```
┌─────────────────────────────────────────────────────────┐
│ 输入层   GamePlay.PlayerController（InputSystem）          │
│          原始设备 → 语义命令（MoveDirection/MoveTo/Attack...）│
└──────────────────────────┬──────────────────────────────┘
                           │ EnqueueCommand
┌──────────────────────────▼──────────────────────────────┐
│ 框架层   FrameSync.GameSync（主控）                        │
│           ├─ 输入发送 SendLocalInput（每逻辑帧打包本帧命令列表）│
│           ├─ 接收广播 ReceiveMessage → FrameBuffer.Push    │
│           ├─ 调度 ApplyFrames：决定"喂哪一帧"，缺帧喂 null    │
│           ├─ 快照上报/恢复 + 重连补发                        │
│           └─ 每玩家一个 FrameBuffer（缓冲/帧号/缺口/追帧）     │
└──────────────────────────┬──────────────────────────────┘
                           │ entity.Simulate(input)
┌──────────────────────────▼──────────────────────────────┐
│ 游戏逻辑层 GamePlay.PlayerEntity（纯逻辑，不感知帧号/网络/缓冲）│
│           Simulate(FrameInput)：确定性模拟（只处理自己的数据）    │
└──────────────────────────┬──────────────────────────────┘
                           │ 读 Position
┌──────────────────────────▼──────────────────────────────┐
│ 表现层   GamePlay.PlayerView（MonoBehaviour）→ transform    │
└─────────────────────────────────────────────────────────┘
```

**一句话：框架决定"喂哪一帧"，实体只回答"这一帧我该干什么"。**

**依赖方向**：框架层（FrameSync）持有并创建逻辑实体（GamePlay.PlayerEntity），实体不依赖框架——单向依赖，文档化约定。

## 二、核心类职责

| 类 | 命名空间 | 归属层 | 职责 |
|---|---|---|---|
| `GameSync` | FrameSync | 框架 | 帧同步主控子系统（房间/输入发送/快照/调度/重连恢复） |
| `FrameBuffer` | FrameSync | 框架 | 每玩家帧缓冲：`Push` 写入、`TryPopNextFrame` 消费（含跳帧容错）、帧号推进 `NextFrameId`/`LastExecutedFrameId` |
| `FrameInput` | FrameSync | 框架↔逻辑 | 一帧的玩家输入 = 命令列表（可同时下达多条命令）；null = 缺口/离线 |
| `InputCommand` / `CommandType` | FrameSync | 框架↔逻辑 | 单条语义命令：类型 + 参数（MoveDirection=键盘方向调试，MoveTo=未来正式移动预留） |
| `PlayerEntity` | GamePlay | 游戏逻辑 | 纯确定性模拟：`Simulate(input)` 只改自己的位置等状态；`SetSnapshotSync`/`GetSnapshotSync` 快照恢复/上报（帧号由框架传参） |
| `PlayerView` | GamePlay | 表现 | 每帧读 `entity.Position` → `transform` |
| `PlayerController` | GamePlay | 输入 | 原始输入 → 语义命令（`EnqueueCommand`） |
| `Command`（proto 生成） | GameMessage | 传输 | 协议层语义命令（oneof：MoveDirection/MoveTo/Attack/Build），`PlayerSync.repeated Command` |

## 三、关键机制

### 1. 帧号权威
服务端统一分配帧号（严格 Lockstep：等所有在线玩家提交输入才广播完整帧）。客户端 `_sendSeq` 只是发送跟踪，`_latestServerFrameId` 是权威帧号。每个 `PlayerSync.frameId` = 服务端统一帧号（客户端缓冲/补发 Key）。

### 2. 缺口/离线语义
`ApplyFrames` 对每个玩家 `buffer.TryPopNextFrame()`：缓冲有下一帧 → 喂输入；**没有 → 喂 null → 实体冻结**（离线期不移动，符合语义）。实体不需要知道缺口原因。

### 3. 跳帧容错
补发时离线/停滞玩家的帧本就不存在 → 目标帧缺失但缓冲内有更晚帧时，`FrameBuffer` 跳到最早可用帧继续。所有客户端收到同一份补发、跳帧一致，不破坏确定性。

### 4. 追帧
缓冲帧数 > `BufferSize(3)` 时每帧多消费 `min(IntSqrt(缓冲数), MaxCatchupTime=5)` 帧，快速追平服务端权威帧。sqrt 用整数开方（避免浮点误差）。

### 5. 快照恢复（断线重连/中途加入，含漂移根治）
```
服务端 SendReconnectData：向【所有在线客户端】统一广播权威快照 + 全量补帧
  → 重连玩家 + 在线玩家全部从同一快照点重置（消除"不同时间点恢复导致的位置漂移"）
客户端 ApplySnapshot: 清空 _players/_frameBuffers → 按快照重建实体
  每个玩家: buffer.Clear() → buffer.ResetNextFrameId(snapshot.LastFrameId) → entity.SetSnapshotSync(snapshot)
执行进度起点 = 各玩家快照帧号 + 1（框架维护，实体不感知）
```

### 6. Desync 检测闭环（2026-08-03）
```
客户端每 30 帧（≈1s）上报世界哈希 HashReportMessage（name + frameId + worldHash）
  → 服务端 RoomManager.ReceiveHashReport 缓存各玩家 (frameId, hash)
  → 跨客户端同帧（±1 帧进度容差）比对
  → 不一致：广播 DesyncNoticeMessage（含分歧帧号）给所有客户端
  → 服务端/客户端双端 Error 日志标记分歧（帧同步最怕静默分歧，此机制是底线保障）
```

### 7. 确定性
位置等逻辑状态一律 `FixedPoint` 定点数（int 原始值传输）。实体内禁用 `Time.time`/`UnityEngine.Random`/浮点比较，保证各端同输入同输出。

## 四、数据流（一帧的完整旅程）

```
① 输入：PlayerController（键盘 WASD）→ GameSync.EnqueueCommand(MoveDirection 命令)
② 发送：TickGame → SendLocalInput：本帧命令列表打包为 PlayerSync.Commands（_sendSeq 序号）
③ 服务端：收集所有在线玩家输入 → 帧号+1 → 广播 GameSyncMessage（含每个玩家本帧 PlayerSync）
④ 接收：GameSync.ReceiveMessage → ToFrameInput(playerSync)（命令列表解码）→ FrameBuffer[name].Push
⑤ 调度：TickGame → ApplyFrames → input = buffer.TryPopNextFrame() → entity.Simulate(input)
⑥ 表现：PlayerView.Update → transform.position = entity.Position
```

## 五、扩展点

- **新操作命令**（攻击/建造/技能）：
  1. proto `Command` oneof 加分支（如 `AttackCommand`）→ 重新生成 C#
  2. `CommandType` 加枚举 + `InputCommand` 加参数字段
  3. `GameSync.ToProtoCommand`/`ToFrameInput` 加映射 case
  4. `PlayerEntity.Simulate` 加 case（确定性实现）
- **MoveTo 正式移动**：`Simulate` 中 MoveTo 的 TODO（需确定性寻路/到达判定）
- **多对象/单位**：`PlayerEntity` 是单玩家示例；未来可抽象 `Entity` 基类，`Simulate` 签名不变
- **确定性 Random/数学**：待办区已记录（sqrt/三角等 FixedPoint 实现）
